# Выбор и настройка мониторинга в системе

## Мотивация

С переходом к оформлению заказов через API система перестала быть полностью наблюдаемой через Яндекс Метрику. Яндекс Метрика фиксирует только пользовательское поведение в веб-интерфейсе, но не покрывает серверные процессы обработки заказов.

Внедрение системы мониторинга и алертинга позволит:
    - добавить наблюдаемость жизненного цикла заказа (end-to-end);
    - точно определять место возникновения ошибок;
    - выявлять деградацию сервисов до появления жалоб пользователей;
    - контролировать SLA (время обработки заказов);
    - снизить финансовые и репутационные риски за счёт быстрого реагирования на инциденты.

## Выбор подхода к мониторингу

RED (Rate, Errors, Duration)

Применяется к пользовательским API (Shop API, MES API, CRM API), так как решает задачу контроля качества пользовательских запросов.

Позволяет получить ответы на вопросы:
    - выдерживает ли система текущую пользовательскую нагрузку (Rate);
    - есть ли ошибки, влияющие на пользователей (Errors);
    - укладывается ли система в SLA по времени ответа (Duration).

USE (Utilization, Saturation, Errors)

Применяется к инфраструктурным компонентам (БД, очереди, storage, runtime API), так как решает задачу диагностики ресурсных ограничений.

Позволяет определить:
    - насколько загружены ресурсы (CPU, память, сеть) — Utilization;
    - есть ли признаки упора в лимиты (очереди, connections) — Saturation;
    - происходят ли ошибки на уровне инфраструктуры — Errors.

## План действий

1. Развернуть Prometheus и Grafana.
2. Доработать API:
    - добавить метрики в Java (Shop API, MES API);
    - добавить метрики в C# (CRM API);
    - реализовать RED-метрики (RPS, latency, errors);
    - добавить USE-метрики (CPU, memory, sessions).
3. Подключить инфраструктурные метрики:
    - подключить RabbitMQ exporter;
    - настроить сбор метрик PostgreSQL (connections, memory, size) для обеих БД;
    - подключить метрики S3 storage.
4. Настроить сбор в Prometheus:
    - описать targets;
    - настроить scrape jobs для всех компонентов.
5. Настроить алертинг:
    - рост HTTP 500;
    - превышение latency SLA;
    - рост очередей;
    - исчерпание connections;
    - высокий CPU/memory.
6. Настроить дашборды в Grafana:
    - API (RED);
    - инфраструктура (USE);
    - бизнес-метрики заказов.
7. Раскатить во все окружения (dev/release/prod)
